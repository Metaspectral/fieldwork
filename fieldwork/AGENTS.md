# Fieldwork development

Read README.md, docs/architecture.md, and docs/first-milestone.md for product direction. The original handoff is historical; current user decisions take precedence.

Preserve the farmer's baseline practice and reasoning. Plugins supplement or propose changes; application code enforces approval for activation, accepted-workflow updates, and publication.

Private records belong to the selected local or hosted runtime. Connectivity, community sharing, and hosted execution are independent choices. Community publishes reviewed summaries rather than private workspace objects.

Keep executable integrations separate from editable methods. Never execute community instructions as trusted code. Record workflow versions, units, inputs, outputs, and sources.

Keep the supplied prototype unchanged as a reference. Label simulated features. Follow upstream package instructions when implementing the runtime; this directory contains Fieldwork-specific guidance and planning.
