# 轮作预算方法

[English](rotation-method.md) | 中文

轮作页面每块田一行，显示所选季节之前三个季节记录的已种作物、该季节的计划作物以及田块遵循的轮作。农户可以用自己的价格、产量和成本，将现行轮作与另一种轮作比较，并把结果保存为经过审核的计划。保持现行轮作也是有效结果。后续版本不会改写此前的计划。

## 已收录的轮作

轮作库覆盖一个地区：南达科他州东部。它收录一项已发表研究的六种作物顺序：玉米–大豆、连作玉米、玉米–大豆–春小麦–向日葵、玉米–大豆–春小麦–豌豆、玉米–豌豆–冬小麦–大豆、玉米–燕麦–冬小麦–大豆。来源为 Bansal、Wang 和 Osborne 2024，Agronomy Journal 116(6):3145–3157，[doi:10.1002/agj2.21688](https://doi.org/10.1002/agj2.21688)。前两种标注为研究中的常规系统，其余四种标注为受试替代方案。

每种轮作都带有来源和局限说明；没有来源的条目无法通过校验。来源分为四类：已发表研究、社区、试验或农户自己的作物顺序。本版本提供已发表研究和农户自定顺序。社区和试验在选择器中显示为暂无收录。

轮作库只保存作物顺序、来源和局限，不保存研究中的任何价格、产量、成本或收益。该研究描述布鲁金斯附近的一个试验点，采用免耕、低投入小区，其成本和收益只覆盖 2017 至 2020 年的一个四年周期。它不能说明其他田块的产量或利润。

## 计算

`rotation-budget-v1` 按每英亩、每个作物年计算。田块面积以公顷保存、以英亩显示；一个国际英亩等于 4046.8564224 平方米。货币为农户选择的 CAD 或 USD。

1. 收入 = 单价 × 每英亩产量 + 每英亩其他收入。
2. 总成本 = 不含土地的成本 + 每英亩土地成本。
3. 利润 = 收入 − 总成本。
4. 轮作每英亩年均利润 = 各作物年利润之和 ÷ 作物年数。
5. 差额 = 对比轮作年均 − 现行轮作年均。
6. 整块田每年 = 每英亩数值 × 田块英亩数。

产量单位为蒲式耳每英亩，向日葵为磅每英亩。结果四舍五入到分。产量、单价、不含土地的成本或土地成本为空的轮作显示为未计算。其他收入可不填，按零计算。

所有数值均由农户输入。轮作的每一年使用相同的价格、产量和成本。计算不假设轮作会改变产量，也不预测产量、土壤变化、天气或价格，不对轮作排序或推荐。

## 记录与审核

计划保存田块、季节、版本、两种作物顺序及其来源、输入数值、带方法版本的结果、保持或更换的决定、计划季节种植的作物以及农户的理由。数值带有一个标签：农户自己的记录、农户的估计或虚构演示。

田块的轮作和计划作物取自最近接受的计划。计划作物不会写入已种作物历史。以下情况拒绝接受：对比计划缺少数值、提案后田块面积发生变化，或演示数值用于非演示田块。

页面操作在保存前显示审核对话框。模型工具 `propose_rotation_plan` 和 `accept_rotation_plan` 需要原生审批；`list_regional_rotations` 和 `read_rotation_plans` 只读取。

## 布鲁金斯示例与农场地图

“加载布鲁金斯示例”在审核对话框后添加三块田块，每块的名称和备注均标明为示例。它们是布鲁金斯轮作研究约一公里范围内的真实田块轮廓，取自美国农业部作物序列边界 2018–2025，并附带美国农业部根据卫星影像判读的各年作物类别。不属于轮作作物的类别（如开发用地或草地）保留为备注，而不作为作物。轮廓是匿名的：没有人确认它们是自己的田块，也不会添加价格、产量或计划。

“我的农场”中的农场地图绘制每块带轮廓或点位的田块，并标注其名称和最近记录年份的作物。所有田块的年份相同时，标签不显示年份。会互相遮挡的标签被移开。地图下方的简短列表说明图片、其影像与数据来源，以及轮廓和作物类型的出处。“获取卫星图片”在审核对话框后，从公开的 Earth Search 目录读取这些田块周围范围的一张晴朗生长季 Sentinel-2 真彩色图片，并保存在记录旁。不会上传任何内容。每个像素约覆盖 10 米，图片显示的是拍摄日期而非今天的情况。没有图片时，或已保存的图片未覆盖之后添加的田块时，轮廓绘制在纯色背景上。选定当前田块后，地图突出显示该田块并淡化其他田块，田块表只显示它那一行，“田块状况”的表格只列出它的季节。

## 验证

领域测试覆盖六个带引用的条目、拒绝无来源条目、虚构输入的预算运算、缺失数值、接受检查、虚构示例、布鲁金斯示例、田块位置、图片定位与保存，以及从架构版本 2 迁移及其备份。浏览器测试加载虚构示例并接受，添加田块，记录过去的作物，比较两种轮作，审核并接受计划，并检查表格。

这些检查验证软件机制及所述局限。轮作决定仍需要适用于当地的证据和农户判断。

本方法的部分代码、测试和文字由 AI 编程助手生成，并由项目团队指导；见 [README](../README.zh.md)。
